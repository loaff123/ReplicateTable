# ReplicateTable throwaway feasibility freeze

This is an approved, original benign-synthetic feasibility probe, not product code. No user datasets or product/public writes are involved. The fixtures and expected outcomes are frozen before candidate execution. All coordinate identifiers retain their exact JSON scalar type; integer identifiers never pass through float.

## Contract

Each fixture is `{id, data, recipe}`. Data contains `coords` and independently dimensioned `variables`, each with C-order flat values, units and dtype. Only selected column source variables participate: unused variables/dimensions must not expand the table. Rows are the Cartesian product of the explicitly named row dimensions. Broadcast dimensions must exactly declare row dimensions absent after reduction. Coordinates must be present, unique, non-null, and finite. Output order is canonical lexicographic by typed exact row keys; support order is column recipe order, stage order, and remaining-coordinate names/typed keys.

Each stage must name its dimensions, operation, missing policy and minimum count. Finite values count toward `n_valid` even at zero weight. `n_positive_weight_valid` counts finite values with strictly positive weights. `weight_total` sums weights over every input cell; `weight_valid` excludes cells with missing/nonfinite data. Ordinary means and extrema have implicit weight one. No support record is emitted for a column without reduction. Weighted stages are allowed only as the first stage, with weight dimensions a subset of the input dimensions; all weight values must be finite and nonnegative.

Status/reason order is `missing_values`, `insufficient_count`, `zero_weight`. Propagate reports missing_values if any input data is missing; skip does not. Minimum count tests `n_valid`, not the positive-weight count. Only weighted_mean reports zero_weight for a zero denominator, independently of minimum-count failure. Unweighted means and extrema report insufficient_count for all-missing groups. min_count must be an integer >=1. All applicable reasons are retained and any reason makes that stage result null. Later stages treat failed intermediate values as missing, under their own explicit policy. Final row reasons are the last stage's reasons; intermediate reasons remain in support records. All-null rows remain present. Final columns may not retain dimensions outside the declared row grain.

Unit-bearing sources require an exact source-unit assertion. Conversion to the declared target happens exactly once on each finite source value before the first reduction; every stage therefore consumes values already in the target unit. The scalar oracle implements only the frozen unit pairs with exact factors: ms to s = 1/1000, degC to K = value + 27315/100, plus exact identity pairs. The adapter must use a generic unit engine rather than fixture-specific conversions. Weighted averaging and repeated averaging of affine temperature units are qualified by F4. No affine sums, products, variances, or unit algebra are claimed.

Numeric expected output is ordinary JSON numbers/null. A parallel `exact` block records every row value and support value/weight sum as a reduced rational string. Comparison tolerance is absolute 1e-12 and relative 1e-12; keys, counts, reasons, dimensions and unit labels compare exactly. Integer keys never receive numerical tolerances.

## Original cases, fixed outcomes

- F1: 2 cases × 2 channels × 2 replicates × 3 samples, response `[0,2,4,2,4,6]` with per-row offsets 0/10/20/30. Sample means are 2/4 + offset; replicate mean is 3/13/23/33. A case covariate broadcasts only over channel, and channel gain broadcasts only over case. Unused sample×bound bounds must not multiply the exactly four rows.
- F2: response `[0,0,0,12,null,null]` plus offsets. Pooled finite-cell means are 3/13/23/33, while equal-replicate means are 6/16/26/36. Pooled support is 6 input, 4 valid; per-replicate support is 3/3 and 3/1.
- F3: same ragged data, sample weights `[1,2,1]`. Pooled means are 12/5 + offset; sample-weighted then equal-replicate means are 6 + offset. Pooled total/valid weight is 8/5. The F3_scaled variant multiplies weights by 7: values and positive counts stay fixed; first-stage weight totals scale by 7.
- F3_support_edges: four rows and two policies freeze distinct zero-weight, missingness, count-threshold and combined-failure outcomes. `zero` has three finite values, zero total weight, and only zero_weight. `partial` has values `[2,null,8]`, weights `[1,100,3]`: skip gives 13/2, total weight 104, valid weight 4; propagate gives only missing_values. `allmissing` gives insufficient_count plus zero_weight (plus missing_values under propagate). `small` has `[5,null,null]`, weights `[0,1,2]`, one finite/zero-positive value: insufficient_count plus zero_weight (plus missing_values under propagate).
- F4: duration ms→s repeated means give 7/2 and 9/2 s. Temperatures `[0,10,30,20,null,40]` degC (second case +100) give sample-weighted then equal-replicate 1472/5 and 1972/5 K; pooled weighted gives 17489/60 and 23489/60 K. Repeated min gives 5463/20 and 7463/20 K; repeated max gives 6263/20 and 8263/20 K.
- F5: exact case keys 9007199254740993 and 9007199254740995. F1-like rows give 3/13/23/null, with the fourth entirely missing. Sample-stage min_count=2 and final min_count=1 retain all four rows and record insufficient_count at every missing group. F5_permuted reverses coordinates and transposes the response dimension order to sample/channel/case/replicate; results and keyed support must be identical.
- F6: an independent replay copy of F1 has identical results. Relocating source files must not affect content identity or semantics. Changing source content while requesting replay against an earlier expected fingerprint must refuse with source_fingerprint_mismatch. Fingerprint enforcement is implemented by the parent, not the oracle.

`frozen_expected.json` holds full row, support, rational, refusal-control and metamorphic outcomes. `oracle.py` is an independent scalar-loop/Fraction evaluator, with no NumPy, xarray or Pint imports. `freeze_sha256.json` binds all oracle-owned artifacts. Any post-freeze change must be explicitly disclosed and independently justified before renewed candidate execution.
