# Selected experimental tmpfs output-parent profile

This supersedes the proposed overlay admission in FILESYSTEM-PROFILE-v1.md; original draft/source companions and successful ABI experiments remain unchanged evidence. Initial support is exactly the named stock CPython3.12/3.13 Linux6.18.44 x86_64 little-endian profile with an anchored tmpfs parent whose actual FS_IOC_GETFLAGS query succeeds and reports CASEFOLD0x40000000 and encryption0x800 clear. Every other filesystem, including overlayfs, refuses before temporary root creation. Unknown kernel/ABI or unavailable feature query also refuses. This is an experimental compatibility-limited backend, not generally usable local-file CLI support. HostedCI on another kernel must explicitly exercise/expect refusal or skip the native-success case; it must not weaken the profile to obtain green results.

Overlay is withdrawn because an ordinary eligible FUSE backing upper can expose fileattr_get and ordinary dentry operations yet delegate name semantics outside the kernel. Overlay's own type and selected attributes therefore do not expose sufficient backing semantics. Seven distinct sampled names cannot prove arbitrary lookup behavior. No hidden backing-path/mount traversal, caller assurance, wider cap or automatic fallback repairs that implication. A future practical direct filesystem may be reviewed only if actually available; it is outside this slice.

The closed consuming helper remains _qualify_output_parent(root,budget)->None in new _native_fs_profile.py. It requires a complete exact acquired active _GeneratedRoot and an existing exact private budget. Ordering: budget checkpoint; complete owner/state and selected-runtime checks; original parent identity stat; native fstatfs on that borrowed FD; require tmpfs; native GETFLAGS on the same FD; require relevant bits clear; original parent identity stat; budget checkpoint. Feature observations never replace original witnesses or become stored tokens. No source/plan/cancellation/reap/commit authority is added. Output and fixed-/tmp non-output roots use the same helper; real creation and final installation independently recheck it at their owning boundary.

Use the agreed shared _native_abi._syscall_binding() tuple/None. Types are fixed at module import: ctypes.c_long*15 for the120-byte statfs structure and ctypes.c_ulong for the8-byte legacy ioctl buffer. Each helper owns only one instance, byref address and explicit-width syscall arguments; it reads errno immediately after-1 and ignores stale errno on success. The statfs buffer helper returns and clears operation locals before GETFLAGS allocates its buffer; the flag helper clears before the final stat/checkpoint. No own CDLL/cache, FD acquisition, stored full path, extra owner/model/ledger or persistent feature record is introduced.

Native ABI calls are syscall(c_long(138),c_int(parent_fd),byref(statfs_storage)) and syscall(c_long(16),c_int(parent_fd),c_ulong(0x80086601),byref(flags_storage)). Exact success is integer0; the initialized flag buffer yields a nonnegative32-bit word. Other shapes fail closed. None binding and ENOSYS/ENOTTY/EOPNOTSUPP are unsafe_path/2 with fixed ASCII message: Output parent lookup semantics are not supported by this runtime profile. Other actual supported-query OSErrors are bounded io_error/3. Existing path/identity and cancellation/deadline errors retain their codes/order.

Zero new persistent/transient descriptors or path roles. Existing root/budget/projection state stays additive. Raw stat observations remain sequential in stat16. Caller/helper frames fit the existing walk8 target; one120-byte or8-byte native buffer plus bounded scalar/address/errno/result wrappers must fit the shared ABI8 lane. Import metadata credit and physical coexistence remain subject to the joint binding/consumer inventory and independent both-profile measurement. Neither paper allocation nor successful experimental ABI queries establish whole-route fit.

The native-success test uses only a newly owned directory under /tmp. Failure fixtures replace finite scalar syscall observations, never set real casefold/encryption flags or mutate mount/security settings. Required tests include exact/partial/retired owner refusal before queries; invalid/cancelled budget; actual tmpfs FD queries and original identity; overlay/unknown type refusal before GETFLAGS; casefold/encryption refusal; unsupported-query and operational errno distinction; wrong syscall result; immediate errno/stale-success handling; original-parent mismatch; unchanged borrowed FD; and operation-buffer retirement even with a retained plain-handler exception. The actual mount qualifier remains separate experimental evidence.

## Source basis

The selected stable kernel's shmem directory operations and file attributes expose its per-directory flags; its user-visible mask includes CASEFOLD. Generic comparison rejects unequal bytes before Unicode comparison when that parent flag is clear. These are the positive implementation premises for direct tmpfs, conditional on the actual successful anchored query. [shmem implementation](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/mm/shmem.c), [visible flag mask](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/include/linux/shmem_fs.h), [generic lookup](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/fs/libfs.c)

The ordinary FUSE lookup and fileattr getter delegate to userspace; ordinary FUSE dentry operations do not provide a positive byte-only lookup proof. Overlay's eligible backing and selected-getter paths do not establish all relevant backing name semantics. No current mount is asserted to have such a backing layer; the source-level counterexample defeats the proposed general implication. [FUSE directory operations](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/fs/fuse/dir.c), [FUSE flag query](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/fs/fuse/ioctl.c), [overlay setup](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/fs/overlayfs/super.c), [overlay attributes](https://raw.githubusercontent.com/gregkh/linux/v6.18.44/fs/overlayfs/inode.c)
