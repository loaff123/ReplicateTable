# Reconstructed public API and exact schemas

Status: new design freeze candidate, 2026-10-06. This file is normative with CONTRACT and RESOURCES. **NEW** plan/manifest/schema/transport/formula formats below are not claims of recovered historical serialization. Recipe=1, result=1, explanation=1 and runtime.binding_version=1 retain available shapes; plan=2, table/stage schema=2, manifest=2, inspection=2, transport=2 and formula=2 intentionally distinguish reconstruction. No silent old-plan/bundle migration. Resource/model implementation must follow exact fields below; named records do not allow arbitrary extra fields.

## 1. Shared lexical and type rules

Canonical JSON is strict UTF-8, ensure_ascii=false, keys sorted by Unicode codepoint, separators comma/colon without whitespace, lowercase true/false/null, Python finite-float repr under the bound runtime, with exactly one final LF. Reject BOM, surrogate codepoints, duplicate keys at every depth, trailing non-whitespace, nonfinite numeric constants, exponent overflow, invalid UTF-8 and depth >32 before retaining an unrestricted parse forest. Input trailing JSON whitespace is permitted; canonical output has only its final LF. Enforce raw byte/lexical bounds before decoding. Preflight uses bounded depth/count state and charges every eventual member/value before full parse. Numeric tokens ≤32 ASCII bytes; integer domain −2**63..2**64−1, counts 0..2**63−1, and finite float64. Exact input bool is not int. Parsed float versus int type remains distinct.

`name`: exact str, 1..128 UTF-8 bytes, no U+0000..001F or U+007F..009F, surrogate, slash or backslash; otherwise opaque (spaces/colon/quotes/HTML punctuation valid). Do not normalize Unicode. `unit` for measurements/weights: null or exact str, 1..512 UTF-8 bytes, no control/surrogate. `raw_coordinate_unit` has the same bound but permits horizontal tab U+0009, preserving the recovered reference-time declaration grammar; a tab-delimited raw coordinate declaration reaches the selected encoding guard rather than a generic measurement-unit check. `digest`: exact lowercase 64-hex str. `dtype`: admitted native numeric dtype canonical name (int8/int16/int32/int64/uint8/uint16/uint32/uint64/float32/float64). Selected Coordinate.dtype uses exact NumPy dtype.str for an admitted native numeric type or `<U<N>` with positive stored width ≤4096. Raw coordinate descriptor/hash-frame dtype is a distinct, route-qualified representation: numeric dtype.str, original `<U<N>`, fixed `|S<N>`, or exact object spelling `|O`, according to §17. Qualified raw object strings acquire selected `<U<M>`, M=max(1,max stored character length), only after complete label qualification. The exact table in §17 controls; metadata Unicode-vector padding has no imported coordinate-width cap. Every stored label fits its dtype. Array rank ≤16; scalar shape=[] is legal; non-scalar lengths ≥1.

`scalar(dtype,nullable=false)` is exact int in dtype range, exact finite float representable by dtype, or exact str within coordinate width/4096 UTF-8 bytes. Null is allowed only where explicitly marked. Raw fixed-width S<N> coordinate descriptors are also admitted for the explicitly described UTF-8 route: N≤4096, precharge N*length bytes, strip trailing NUL padding, strict UTF-8 decode, canonical Coordinate dtype <U<N>. For native VLEN and owned object-string coordinates, canonical Unicode width is max(1,max decoded stored character length); a preexisting exact memory Unicode dtype preserves its stored width. Object bytes are never ordinary string labels.

Numeric sign-zero is retained in canonical output. No Python numeric subclasses or cross-type comparisons. Exact dict/list inputs are accepted where the public schema calls for them; models own immutable internal tuples/maps and do not retain mutable aliases. Bounded MappingProxyType is accepted only at the explicitly documented internal model/runtime seams.

`reasons` is a unique subsequence of [missing_values,insufficient_count,zero_weight] in that order. `source` is exactly {kind:"memory"|"file",sha256:digest,size_bytes:count}. Private backing handles, stat witnesses, paths and Dataset objects are never fields in canonical output.

`CallAdmission` exact fields: {version:2,formula_version:2,baseline_bytes:count,extra_source_bytes:count,cache_bytes:count,total_bytes:count,limit_bytes:536870912,admitted:bool,required_dataset_count:int[0,3],distinct_dataset_count:int[0,3]}. Required count counts occupied slots before identity dedup. No Dataset IDs/paths appear. The three byte terms sum exactly to total; admitted iff total≤limit. A full diagnostic is returned only if all known state was measured within the bounded accounting domain.

## 3. Recipe version 1

Root exactly {version:1,row_dims:[name, ...],columns:[ColumnRecipe, ...]}. row_dims unique, ≤16; columns 1..32. A ColumnRecipe exactly {name,source,source_unit,target_unit,broadcast,stages}. name unique among columns; logical row and column name spaces are separate, so same spelling is legal. source is a descriptor data-variable name. broadcast is a unique ordered name list. stages has length 0..2 and stage names unique within the column.

Unweighted StageRecipe exactly {name,dims,op,missing,min_count}, with op mean|min|max. Weighted StageRecipe exactly {name,dims,op:"weighted_mean",missing,min_count,weights,weight_unit}. missing is skip|propagate; min_count is exact int 1..67108864. dims nonempty ≤16; weights a variable name; weight_unit null/unit exact assertion. No weights/weight_unit field is legal on unweighted stages. Missing weight_unit is invalid current recipe. The original fixture adapter may append null on a newly allocated test-only recipe for a historical unitless weighted stage; originals remain unchanged.

## 4. Inspection and source models (NEW serialization)

Inspection JSON exactly {version:2,source,dimensions,variables,coordinate_descriptors,attributes}. All maps ordered canonically.

- dimensions: map name -> exact positive count
- variables: map name -> VariableDescriptor
- coordinate_descriptors: map dimension name -> VariableDescriptor for available dimension coordinates; an absent coordinate stays absent and later selected use refuses
- attributes: typed MetadataValue described below
- VariableDescriptor exactly {dims:[name...],shape:[positive count...],dtype:str,unit:unit,attributes:MetadataValue,encoding:MetadataValue,selection_status:SelectionStatus|null}
- SelectionStatus exactly {status:"unsupported",code:"unsupported_coordinate_encoding"|"unsupported_source_encoding",reasons:[EncodingReason...]}, no duplicates and at least one. Coordinate descriptors use the coordinate code; data-variable descriptors (including later weight selection) use the source code. The exact role-valid finite reason vocabulary/order and declaration rules are §16. There is no new status field

For coordinate descriptors, VariableDescriptor.unit is raw_coordinate_unit from attributes, and both attribute/encoding raw unit declarations permit horizontal tabs. Do not feed them through measurement/weight-unit validation before selection: tab-delimited reference declarations must inspect successfully and then refuse selected use with unsupported_coordinate_encoding. Calendar strings stay separately bounded.

Authoritative measurement/weight unit is the attributes["units"] label, after only the explicitly admitted scalar metadata bridge in §17: absent or null gives null; a present non-null value must yield the bounded nonempty exact unit string, otherwise invalid_source. This permits the qualified exact np.str_ route but no arbitrary coercion or altered label text. Encoding["units"] never overrides the assertion unit, but its raw declaration remains bound. For coordinate time detection, either attributes or encoding units may trigger refusal, including when they conflict; null/absent encoding units do not trigger, and a present non-null non-string units declaration refuses invalid_source at inspection. Calendar key presence triggers selected refusal even for null/numeric/empty values. No conflicting declaration is silently discarded or normalized.

Supported descriptor attrs/encoding are finite bounded trees of exact primitive scalars, list/tuple and string-keyed dict, plus prequalified stock NumPy scalar/small-vector attributes converted without arbitrary callbacks. MetadataValue is injectively tagged: {type:"null"}; {type:"bool",value:bool}; {type:"int",value:int}; {type:"float",value:finite float}; {type:"float_special",value:"nan"|"+inf"|"-inf"}; {type:"str",value:str}; {type:"list",items:[MetadataValue...]}; {type:"map",items:[[str,MetadataValue]...]}, map items sorted with unique keys. No untagged ambiguity. A metadata string is ≤4096 UTF-8 bytes except stricter unit/calendar limits. Attributes/encoding collections obey RESOURCES. Selected coordinates containing unsupported data still refuse even if an editable derived status is removed.

Auxiliary/scalar/multidimensional coordinates outside exact same-named one-dimensional dimension coordinates refuse unsupported_source_storage before their buffers are read. Every accepted source coordinate therefore has a complete dimension-coordinate descriptor.

Native coordinate classification is metadata-only and exact: a root variable whose name is a declared dimension and whose dimensions are exactly [that name] is a dimension coordinate. In addition, read only the exact `coordinates` attribute on the root and on each root variable. Absent means no declaration. A present declaration must be one exact bounded UTF-8 string of at most4096 bytes; empty/ASCII-whitespace-only is legal and means no names. Split only on ASCII whitespace U+0009..000D/U+0020, with at most80 tokens; preserve token spelling/case/Unicode exactly, validate each against name rules, and reject duplicate tokens within one declaration or missing root-variable references as invalid_source. The same name repeated across different declarations is one membership fact. A referenced variable is declared coordinate membership; if it is not already a same-named one-dimensional dimension coordinate, refuse unsupported_source_storage before any array payload is read. No substring matching, calendar decoding, inferred semantic coordinate role, or shape-only classification. `bounds`, `grid_mapping` and other metadata do not confer coordinate membership in this first version and remain bound raw metadata. Scalar/multidimensional root variables with no such declaration remain ordinary data variables, whether selected or not. In-memory classification uses exact Dataset coordinate membership, not attrs-derived guesses.

This deliberate coordinate narrowing reduces ordinary xarray/NetCDF compatibility. The safe refusal message is "Only same-named one-dimensional dimension coordinates are supported; auxiliary coordinates are unsupported." Source data/metadata are never modified to make them fit. Unknown/malformed declaration text uses invalid_source with a fixed safe declaration message; no private path or raw exception appears.

Exact in-memory Dataset root _encoding must be None or an exact empty dict before payload reads; otherwise unsupported_source_storage with no mutation. There is deliberately no new Inspection/root-encoding field. The direct native adapter binds actual file attributes/storage metadata; temporary backend housekeeping is outside this user-Dataset root restriction.

SourceSnapshot private/public in-memory fields exactly: identity, dimensions, variables, coordinate_descriptors, attributes, arrays, coordinates, _handle. Canonical inspection omits arrays/coordinates/_handle. `_handle` is the original exact memory Dataset or safe supervised file reference, with descriptor backing but no unselected prepared buffers. ArrayBuffer owns immutable bytes, exposes only fresh readonly zero-copy views, and contains dtype/shape/byte length validated before access. Coordinate owns its selected dtype, immutable physical-order scalar tuple, and sorted_indices as immutable permutation of 0..length−1. Raw descriptor-to-selected-dtype comparison follows the exact route relation in §17, not blanket string equality. Row membership never mutates it.

Memory identity stream (NEW) is UTF-8 canonical JSON header `{format:"replicatetable-memory-source-v2",descriptor:<inspection-without-source>}` followed by framed payloads in coordinate-name then variable-name order. Each frame is: 8-byte unsigned big-endian length of canonical `{kind,name,dtype,shape}` header; that header bytes including LF; 8-byte unsigned big-endian payload byte length; exact payload bytes. Numeric and admitted fixed S<N> coordinate payloads are exact physical C-order logical bytes; S<N> identity includes all N*length raw bytes including trailing NUL padding and raw |S<N> dtype, even though selected labels decode without padding. Unicode/object coordinate payload is canonical JSON array of typed scalar metadata tokens in physical order. Header ends with LF; no other delimiters. size_bytes counts every framing/header/payload byte. Header/payload length arithmetic is checked before encoding. Source hash is independent of array owner capacity and pandas caches. Native identity is the file-byte hash, not this stream.

## 5. BoundPlan version 2 and rebind

Plan JSON exactly {version:2,formula_version:2,source,recipe,runtime,coordinates,selected,columns,resource_binding,estimates}.

- coordinates: map exactly D -> {dtype:str,values:[typed scalar...],sorted_indices:[int...]}; values are physical order, never source objects. This is the only serialized coordinate-value forest in a plan
- selected exactly {variables:[name...] sorted,dimensions:[name...] sorted,numeric_bytes:count}
- resource_binding exactly {kind:"memory"|"file",base_bytes:count,owners:[OwnerCharge...],descriptor_bytes:count}; owner entries sorted by (kind,name). OwnerCharge exactly {kind:"coordinate"|"variable",name,terminal_bytes:count,header_bytes:count,logical_bytes:count}. Identity/address/inode/cache is omitted. File owners=[]; file base reserves file byte length plus descriptor/model storage. Memory base charges complete retained Dataset/owner/metadata footprint per RESOURCES
- columns is recipe order of CompiledColumn
- CompiledColumn exactly {name,source,source_dtype,input_dims,input_shape,final_dims,broadcast,output_dtype,unit_operation,weight,stages}
- weight is null or exactly {source,dtype,dims,shape,unit_operation}; dimensions stay physical source order
- CompiledStage exactly {name,dims,op,missing,min_count,input_dims,input_shape,remaining_dims,remaining_shape,support_dims,support_count,support_start}; support_dims are remaining dimensions sorted by name; support_start is the complete global support block offset
- estimates is the exact scalar field map listed in RESOURCES; resource calculations exclude the estimates object itself and then include a fixed finite estimate-block bound, preventing self-reference

Output dtype is source_dtype for zero-stage scale=1,offset=0, otherwise float64. final_dims preserve physical source order after removal. Support cardinality is product of remaining_shape, including the scalar product 1.

UnitOperation (recovered exact shape) has {source_unit,target_unit,scale,offset,parsed_source,parsed_target,definition_graph}. Parsed terms are null or sorted arrays of [canonical_name,finite exponent]. Graph is sorted by name; node exactly {name,converter:"ScaleConverter"|"OffsetConverter",scale,offset,is_base:bool,reference:[[name,finite exponent]...]}. It is reachable-only, closed and acyclic, ≤128 nodes, ≤512 total reference terms, ≤64 KiB conservative JSON. Scale is finite positive; offset finite. Null measurement identity has both parsed=null and graph=[]; null weight normalization has parsed_source=null, parsed_target=[], graph=[], effective dimensionless. Stock-Pint representative values cross-check recursively derived affine coefficients. Arbitrary unit parser side effects are never caller-supplied. The NEW bounded stock qualification, pre-cancellation checks and private lifetime rules are normative in §18; they add no serialized fields.

Plan semantic fields are every field except resource_binding/estimates; source fingerprint binds data semantics, while resource_binding binds the compiled baseline capacity. `load_plan(raw,B)` validates cheap held expected source identity first and phase second, then follows §17’s route-specific pre-semantic/runtime/admission gates before recompiling semantic fields against actual B. For a standalone persisted plan, B becomes the new anchor and its resource_binding must exactly match the saved binding; otherwise source_resource_binding_mismatch, not an unannounced different plan. Existing execute(plan_A,B) instead retains A's saved binding, but before granting its non-cache baseline credit a fresh complete safe scan of actual A must reproduce the full exact resource_binding (kind,base_bytes,ordered owners,descriptor_bytes). This includes shrinkage and redistribution among recorded owner/container charges, not only growth or a changed grand total. Any mismatch gives source_resource_binding_mismatch; the saved plan/binding/estimates are never silently rewritten, and A's change is not charged as X or C_cache. After valid anchor credit, distinct B is charged as X and actual B supplies replay. Existing source_bytes_limit and unsupported_source_storage precedence during the scan is unchanged. Equal footprint is not proof that unused A's contents are unchanged; only consumed inputs undergo the required semantic source validation. A physically different but semantically identical B cannot silently replace A or inherit its capacity credit. Selected Coordinate objects on BoundPlan/private backing are identical instances. Reusing the original descriptor for another selection remains required.
