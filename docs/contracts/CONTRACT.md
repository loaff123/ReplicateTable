# ReplicateTable reconstruction contract

Status: DESIGN FREEZE CANDIDATE, 2026-10-06. No implementation, installation, numerical qualification, or release is implied. Design review is required before product work. This is a new reconstruction from explicit requirements and recovered authored materials, not a restoration of missing source or its historical test results.

Normative companions: `API-SCHEMAS.md`, `RESOURCES.md`, `NATIVE-LIFECYCLE.md`, and the gated execution plan `PLAN.md`. Where this contract introduces a previously unavailable field, limit, coefficient, or representation, it is a **NEW** design decision. Known recovered numerical, runtime, source-phase, ownership, admission, explanation, and commit requirements remain requirements. An implementation may not silently simplify one of them or increase a cap. Any material change requires a versioned amendment and fresh affected evidence.

## 1. Purpose and scope

One trusted, small, ordinary local root NetCDF4/HDF5 simulation dataset, or one exact eager in-memory `xarray.Dataset`, is converted into an explicitly chosen row grain and zero-to-two ordered reductions per column. The supported journey is inspect → plan → build → explain-row → verify. Linux x86_64, little-endian, stock pinned CPython 3.12/3.13 profiles are the qualification targets.

The user chooses aggregation. The product makes no independence, effective-N, statistical/scientific correctness, novelty, speed, adoption, authenticity, or hostile-parser claim. Competent xarray/Pint/pandas parity is a required comparison. Exact same-engine replay is consistency evidence, not an independent proof. No remote URLs, private/clinical/production data, arbitrary callbacks, expressions, plugins, custom Pint definitions/contexts, non-root groups, multifile combination, calendars, or distributed/lazy execution are supported. Refusals are part of the supported behavior. The fourteen original frozen refusal controls retain their exact codes, including residual_dimension, duplicate_row_key, unapproved_broadcast, missing_unit_assertion, unsupported_later_stage_weights and missing_stage_policy; API-SCHEMAS §15 fixes their narrow scope/precedence without translating expectations or weakening semantics.

## 2. Strict data and numerical semantics

### Recipe and row grain

- All recipe keys, values, names, arrays and mappings have exact types; bool is never an integer. Duplicate/unknown keys, expressions and implicit defaults refuse
- `row_dims` is an ordered list, including the legal empty list for a scalar row. Output is its Cartesian grain, ordered lexicographically by the coordinate's exact homogeneous scalar type, with the first row dimension varying slowest
- Each output column names one source variable, an exact source-unit assertion including null, a target unit including null, an explicit broadcast list, and zero, one, or two ordered named stages
- Every stage explicitly supplies dimensions, one of mean/weighted_mean/min/max, skip/propagate, and integer min_count ≥1. A weighted stage can only be first and additionally supplies a weight source and exact weight-unit assertion
- Stage dimensions are nonempty, unique, present in the current input, and disjoint from row dimensions. A removed dimension cannot reappear. Final dimensions must be a subset of row dimensions. Broadcast must be exactly the missing row dimensions in row_dims order; it records repetition, not independent observations
- Unselected variables and dimensions never expand the row grain. Source physical dimension order is retained for lineage; stage support serialization uses remaining dimension names in Unicode order and exact typed coordinate order. The reducer may retain a different physical ndarray order, but serialization must follow this rule
- Names are opaque bounded strings, not expressions or paths. Reserved-looking logical names such as n_valid, stage, value and key:00 are valid. Physical CSV names never derive from their content

### Coordinates and types

Every selected dimension, including every reduced or weight dimension, has a one-dimensional exact coordinate of the correct length. Raw descriptor/hash-frame dtype is distinct from selected Coordinate.dtype under the new §17 source table: raw object stays |O, selected all-string object becomes qualified Umax, proved original U<N> stays exact, and fixed S<N> stays raw while selected labels use U<N>. No source storage is certified by a structural constructor. Selected coordinates must be unique, nonmissing and finite. Numeric types are signed/unsigned integers through 64 bits and IEEE float32/float64; strings are ordinary strict UTF-8 Unicode. No bool, datetime, timedelta, complex, structured, subarray, dtype-metadata or arbitrary object measurement arrays. Integer keys and direct integer values never pass through float.

All dimensions are nonempty. Numeric labels are normalized only to the matching exact Python int/float scalar, never across types. A coordinate cannot mix scalar types. Duplicate +0.0/-0.0 labels refuse as equal; a single signed zero retains its stored sign. Query 0.0 may locate stored -0.0, but the returned key is stored -0.0. An integer query does not match a float label. Float32 values retain exactly representable binary32 values when direct. A source string coordinate's stored Unicode width is part of its dtype; every stored label must fit both that width and the 4096-byte UTF-8 limit. A valid over-width query string is a membership miss, not a malformed query.

Descriptor-only object coordinates may contain exact strings, None, and exact built-in nonfinite float sentinels. Identity represents sentinels injectively using typed markers. They do not become admitted selected labels. Selection refuses `missing_row_key` for missing row coordinates and `missing_coordinate` for missing non-row coordinates; nonmissing invalid labels have their own refusal. Object coordinates must own their immediate array and undergo full safe element-type/byte qualification before any copy, hash or label decoding. HDF5 VLEN measurements are unsupported. Native fixed-width S<N> and exact immediate in-memory ndarray S<N> coordinate storage are admitted only via strict UTF-8 decoding after N*length raw-byte precharge; N≤4096. Remove trailing NUL padding, preserve interior characters, reject invalid UTF-8. Raw descriptor dtype stays |S<N>, canonical Coordinate.dtype is <U<N>; report/CSV label dtype is that exact canonical dtype. Arbitrary object-bytes remain unsupported, including stock wrapper paths that erased the fixed-width dtype into bytes objects; no guessed former width.

The ordinary string-coordinate-only VLEN exception has supervised trusted-native preallocation limits, not a guarantee that native allocation is bounded before the library returns.

A selected coordinate with the exact calendar key in attributes or encoding refuses, regardless of its value. A raw units declaration matching the anchored reference-time grammar in API-SCHEMAS also refuses. The guard applies to the whole selected dimension union before coordinate preparation, including already-prepared coordinates. Raw attribute and encoding declarations remain separate and inspectable; derived selection_status is informational and must be recomputed from the declarations. Native inspect hashes file bytes and reads metadata without indexing coordinate arrays. No CF decoding or calendar interpretation occurs.

### Raw declarations: no unpacking or finite-sentinel masking

For selected data, weights and dimension coordinates, exact attrs/encoding packing keys scale_factor/add_offset and _Unsigned presence refuse; their values are never guessed to mean identity or false. Exact _FillValue/missing_value declarations permit only safely admitted scalar NaN on floating storage. Finite/inf/null/string/container sentinels and incompatible storage refuse, before selected payload interpretation. Allowed NaN metadata never permits NaN weights or missing/nonfinite selected coordinate labels. Both declaration locations remain separately bound, with finite ordered unsupported status for unselected inspectable variables. Native backend housekeeping is distinguished from explicit named declarations; whole-file identity remains intact. API-SCHEMAS §16 defines exact presence/type/role/precedence rules and resource projections. No CF decoding or source mutation is introduced.

### Values, conversion and support

NaN measurement values represent missingness; infinite measurements refuse `nonfinite_value`. Finite conversion/reduction/normalization/product/sum/division that produces a nonfinite number fails `numeric_overflow` (operational exit 3), rather than inventing missingness. Direct zero-stage NaN yields null with [missing_values]. Direct identity integers cannot be null.

Qualify even an identity unit with stock pinned Pint. Null source permits only null target. Null target retains the exact source label. The exact assertion compares raw label strings, so physically equivalent aliases do not satisfy a different assertion. Only compatible multiplicative or positive-affine conversion is supported. Apply conversion once to each finite original value before any reduction. Identity direct numeric data retains original dtype; all nonidentity conversions and all staged computations use float64. No custom registry, contexts, logarithmic or arbitrary nonlinear transform is inferred.

The bounded stock-unit grammar and lifetime rules in API-SCHEMAS §18 are explicitly NEW reconstructed choices. Before evaluation, admit only qualified stock names/aliases, multiplication/implicit multiplication/division/grouping, reciprocal/dimensionless literal 1 and signed bounded finite literal powers. Numerical-expression powers refuse. Qualify every raw name's stock definition lineage before cancellation; canceled unknown/logarithmic/offset compounds do not bypass refusal. Offset syntax is only one name, optionally grouped or under one literal power equal to 1. The unchanged seven-field UnitOperation serializes only its canonical reachable graph; exact raw assertions remain exact strings.

One unexposed process-owned stock registry is used under a private nonblocking owner-thread context, from first lazy initialization through complete restoration. Each semantic pass permits at most 64 qualification attempts, including failures and weights. Initialization has one construction attempt; failed initialization or unestablished restoration permanently poisons that private state. Guard token/tree frames and private dependency-error frames must be released before later stock parsing or a fresh sanitized public Refusal. This adds no public registry/context API, caller GC/cache mutation, general heap traversal or prohibition on unrelated memory-route threads. The 512 KiB parser reservation is inside the existing 128 MiB runtime allowance; runtime/source/compiler admission and final implementation qualification remain separate.

The arithmetic family is unscaled float64 operations: per-value affine multiply/add; dimensionless weight normalization; weighted products; an ordinary mean’s sum of finite values followed by division by n_valid; weighted numerator and independently accumulated total/valid weight sums followed by division. Every performed nonfinite intermediate from finite operands is numeric_overflow, even if a mathematically rescaled final mean could be finite. No overflow-avoiding rescaled algorithm is promised. Exact deterministic accumulation grouping belongs to the pinned implementation; the contract does not mandate an order merely to produce a particular rounded support triple.

Weights are finite, nonnegative and dimensionless after stock-Pint multiplicative normalization (percent is valid). Negative/nonfinite weights refuse even if the corresponding measurement is missing. Weight dimensions must be a subset of the original measurement dimensions; named alignment must use views, never tile/repeat. Each physical weight value is normalized once. A zero-weight finite measurement still contributes to n_valid; n_positive_weight_valid is separate. Missing measurements never enter the denominator.

For each stage group, retain n_input, n_valid, n_positive_weight_valid, weight_total, weight_valid, value, unit and every applicable reason. Ordinary mean/min/max use implicit weight 1: positive count=n_valid, total=float(n_input), valid=float(n_valid). Weighted totals include every aligned weight; valid totals exclude missing inputs. Reasons have fixed unique order:

1. missing_values iff propagate and n_valid != n_input
2. insufficient_count iff n_valid < min_count
3. zero_weight iff weighted_mean and weight_valid == 0

Any reason makes the stage value null. A failed intermediate is a missing value for the next stage, which applies its own policy; final row reasons are only those of its last stage. All-null rows and complete intermediate support remain present. No stage exists for direct columns.

Retain actual separately rounded float64 sums. In particular, total=10000000000000000.0, valid=10000000000000002.0, value=0.9999999999999998 is legal. Do not clamp, replace, or enforce exact subset inequality. Local structural validation accepts V≤T or math.isclose(V,T,rel_tol=(n_input−1)*2**−52,abs_tol=0), with exact zero/count constraints. This envelope is not a numerical proof. Frozen oracle/baseline comparisons use abs/rel 1e−12 for numeric results only; same-engine replay uses exact canonical bytes under a matching binding.

## 3. Source qualification, phase and identity

For the in-memory route, the exact Dataset root _encoding must be None or an exact empty dict; nonempty/other state refuses unsupported_source_storage before payload reads and without mutation. Variable/coordinate encoding remains bound as specified. The native route reads actual file attributes/storage metadata directly; temporary adapter/backend bookkeeping is not semantic root encoding and does not reject ordinary files.

Auxiliary, scalar-coordinate and multidimensional-coordinate variables not serving as exact same-named one-dimensional dimension coordinates are unsupported; refuse them during descriptor topology qualification before buffer reads. Unselected ordinary data variables remain allowed. This first-version narrowing reduces ordinary xarray compatibility; native coordinate membership follows only same-named one-dimensional dimension variables and exact bounded `coordinates` declarations, never scalar/multidimensional shape alone. Bounds and undeclared scalar/multidimensional data variables remain ordinary data. The exact metadata-only rule and safe refusal wording are API-SCHEMAS §4.

The source adapter must qualify exact stock xarray Dataset/Variable/IndexVariable, stock supported pandas Index wrappers, and exact ndarray storage before asking for data. Lazy/backends, subclasses, memmap/mmap, unsupported exporters and arbitrary object data refuse before materialization/callbacks. Supported xarray coordinate index wrappers are inspected only through explicitly audited stock storage fields; no `.values` call may silently realize an unknown backend.

For a compiled selection S (distinct measurement/weight variable names) and D (all dimensions occurring in S plus row_dims), the only legal array/coordinate sets are:

- descriptor: A={}, C={}
- prepared: A={}, C=D
- materialized: A=S, C=D

These are exact sets, including scalar coincidences, never subsets/supersets. A BoundPlan retains arrays={} and precisely its selected immutable Coordinate instances, shared by identity with its private descriptor backing. It retains neither a broader prepared snapshot nor a materialized forest. To compile a new selection, use the original inspection descriptor, not an existing plan's selected backing.

If an expected identity exists, compare the cheap already-held identity first, then validate phase, then do expensive source/runtime reads for a legal phase. Never rehash merely to find stale data behind an invalid phase. Actual materialization and execute(plan_A, supplied_B) consume and rebind B. Unused A may be safely footprint-validated without data hashing; if later consumed/rechecked, it must be content-validated then.

### NEW source identity framing

SourceIdentity is {kind,sha256,size_bytes}. File identity is SHA-256 of exact ordinary file bytes and their length, independent of pathname. Memory identity hashes a versioned framed canonical stream: complete bounded descriptor plus the C-order logical payload of every data variable and coordinate, ordered by names; numeric payload bytes use admitted native dtype representation; Unicode/object-coordinate payload uses typed scalar tokens. Float sentinel tokens distinguish nan/+inf/−inf and null; string tokens cannot collide with them. Metadata and encoding declarations are bound. Signed zero and integer widths are preserved. `size_bytes` is exact length of this logical framed stream, counted while hashing; source ownership capacity is not part of identity.

Memory descriptor inspection necessarily reads its already-eager buffers for identity but does not construct selected Coordinate objects; file descriptor inspection never indexes native coordinate values. This distinction is explicit. No identity promises that concurrent mutation is prevented. Fingerprints do not depend on pandas lookup caches, owner over-allocation, private path, inode, timestamp or installation prefix. Memory/file identities are different domains, even when values match. Identity requires a stable source through each operation; content/stat rechecks detect some changes, not locks.

### Retained owner accounting

An immediate numeric ndarray must be exact, native-endian and C-contiguous. Legal C-contiguous singleton axes may have zero/negative strides; readonly is legal. Follow exact ndarray `.base` chains of at most 32 nodes, rejecting a cycle/deeper chain before reads. Terminal storage must be an exact owning C/F ndarray or exact immutable bytes. The immediate view can be C while its owner is F. Reject unsupported exporters before reading payload. Object coordinates have stricter owned immediate storage.

Charge the whole terminal allocation plus conservative safely measured retained headers, separately per variable/coordinate, without unproved alias credit. Do not charge only a selected view. No general heap/GC traversal. Numeric semantic hashing uses logical bytes, not unrelated owner capacity. Resource checks first qualify every owner/metadata/object-coordinate boundary in a complete bounded prepass, then hash; preserve the substantial-owner incremental-metadata charge and its source_bytes_limit precedence. The newly reconstructed finite metadata bridge and exact raw np.str_ reserve are API-SCHEMAS §17: Unicode metadata may be wide padded/U0, but only actual bounded UTF-8 strings enter the final tagged tree. Complete-source pass1 finishes every owner/raw value/codeunit and aggregate bound before any normalized string/tag/list prefix; pass2 builds one final tree. No coordinate-width cap is imported into metadata padding, and no padded Unicode scalar is copied to discover its length.

## 4. Call-local admission and runtime binding

A semantic operation establishes `_required_inputs(plan=...,snapshot=...,result=...,dataset=...)` and preserves the outer context through nested helpers. A result argument without explicit plan is invalid_plan_input. At most the three known explicit source/plan/result Dataset slots are retained, deduplicated solely by Dataset identity. Nothing scans arbitrary caller heaps.

A's canonical bound-plan footprint receives baseline credit exactly once, only after safely remeasuring its current non-cache footprint and requiring exact full resource_binding equality with the saved binding. Growth, shrinkage or changed owner/container charges represented by that binding refuse source_resource_binding_mismatch with clear replan guidance; a comparison of only a total or a less-than-or-equal size is insufficient. Existing source-cap/unsupported-layout precedence is retained. This does not hash same-footprint content in unused A or expand the bounded stock-field/owner scan; consumed inputs still require full source validation. Distinct equivalent B/C are extra validated base footprints X while A lives, not substitutes for A. Existing known bounded stock pandas cache storage C is freshly measured without constructing, clearing, callback traversal or lookup. The finite stock profile includes already-present BlockValuesRefs reference-list storage without dereference/callback, RangeIndex cached _data and Index cached _isnan, charged exactly as RESOURCES specifies without creating or clearing them. Unsupported state refuses. Canonical P_input, fingerprint and plan are cache-independent. Admission is max(E_build,E_verify,E_explain)+X+C ≤512 MiB, with mandatory bounded preallocation/domain checks and route-specific complete guards before new selected allocations/semantic use and at growth boundaries. Complete within-domain diagnostics may return admitted=false. Aggregate accounting beyond the bounded domain refuses without presenting a partial diagnostic as complete. Rechecks detect growth, not hostile concurrent mutation resistance.

The full recovered runtime.binding_version=1 scope is retained: exact executable and actually mapped libpython bytes, supported build/ABI descriptors, selected stdlib code, the exact 15-distribution pinned payload/metadata closure, product resources and Pint stock definitions. Do not substitute version strings for bytes. No absolute paths, environment variables or installer provenance enter public binding. Runtime inventory policy and caps are frozen in API-SCHEMAS/RESOURCES.

Fresh actual runtime qualification is required before semantic fingerprint/conversion/Pint and at final success/commit gates. The newly reconstructed route schedule in API-SCHEMAS §17 permits bounded pre-semantic eager/held-descriptor structure and declaration refusals before runtime; fresh native access still requires early worker runtime and actual declaration rechecks. For an active plan, complete Baseline+X+C must pass before new selected Coordinate/ArrayBuffer allocation; compilation without a plan uses complete standalone/local reservations and checks the derived full baseline before exposing a plan. There is no universal joint-fault ordering across these routes. The first qualified process binding becomes an immutable witness. Actual discovery drift/failure after that latches restart-required state; wrong/malformed caller expectations do not. No hot reload, mtime-only trust, persistent witness cache or user-supplied trusted shortcut. Matching binding is necessary for replay, not whole-OS attestation or proof of previously loaded code provenance.

## 5. Output, verification and report

A bundle contains seven exact root files and one CSV/schema pair for each stage, specified in API-SCHEMAS. Typed CSV/schema preserves original logical names, exact dtypes, nullable float values, integer range, empty strings and effective units. Collision-free positional physical names encode no logical name. CSV strings are data, not formulas to execute. Canonical recipe/plan/result/manifest are strict versioned JSON. Public digests contain no absolute private paths.

Writer streams the caller's immutable result per record/scalar, checks actual component and aggregate bytes before writes, and performs fresh source/runtime binding and exact shared-engine replay before installation. Structural constructors are not numerical proof. A coherent forged result can pass a constructor but must fail public replay. An impossible adjacent-stage lineage must fail replay even when every record separately passes local validation.

Verification reports separate checks for structure/hashes/typed duplication, source binding, runtime binding, exact same-engine replay and regenerated report conformance. It preserves completed versus unattempted checks and the first established finding across nested runtime failures/cancellation. Parsed and validated helper forests must be released at actual frame boundaries before fresh replay; never retain a fourth result forest. The caller's result, if any, remains explicitly charged.

The escaped self-contained HTML report has no network dependencies or executable script. It contains a 100-row table preview, at most 100 records per stage preview, complete row/support totals, aggregate reason counts by column/stage, effective units, declared repetition, source/recipe/plan/result/runtime hashes, verification limitations and the fixed notices. Exact report bytes must regenerate identically.

Coordinate headers use exact Coordinate.dtype. Labels display as ASCII JSON scalars; literal spaces inside displayed strings become visible backslash-u0020. Apply html.escape(...,quote=False) only in text nodes; every emitted character fragment is ≤12 UTF-8 bytes. Actual string/CSV values are unchanged. The extra report notice is exactly 222 UTF-8 bytes, frozen in API-SCHEMAS. Include the per-header 3+6*UTF8(dtype), and two displayed quotes per string-key cell, in the resource bound.

## 6. Row explanation

`explain_row(plan,source,result,key,*,limit)` accepts an exact dict with precisely row_dims and exact int limit 1..1000; there is no default. Keys validate exact scalar type and byte bound before membership search. Linear scan over immutable coordinates creates no pandas lookup cache. Return the stored labels, including signed zero.

Perform one complete exact replay before tracing. Release replay result, validators, helpers and iterators before the second selected-source materialization. Maximum selected payload liveness is caller plus new selected union; no hidden rebound-plan forest. Raw/converted values, physical indices, exact labels, raw/normalized weights and eligibility exclusions are displayed. Stage record offsets refer to complete support blocks. Membership selectors identify omitted predecessors using the source/plan/result hashes. Use an O(rank) odometer, not Cartesian pools or full-row copies.

Construct the complete mandatory empty-display skeleton first. If it exceeds the 8 MiB limit, refuse. Sections are column order, source section then stages; records use physical source order or canonical support order. Apply per-section cell limit. At the first byte overflow anywhere, stop all later display globally. Exact total/shown/limit_omitted/byte_omitted counts still describe every section; total=shown+limit_omitted+byte_omitted. No later short record may sneak through. See RESOURCES for the immutable-owned model, one-record scratch, Unicode/token/traversal/finalization costs.

Serialization walks fields/scalars into an exact bytearray plus final bytes, with ≤32 traversal frames. No full Unicode document, to_dict, freeze/thaw forest, all-chunks list or hidden source/result/plan handle survives in RowExplanation.

Mandatory constructor repairs relative to recovered v1:

- exact primitive types precede comparisons/branching for assurance, notice, stage operation, weight unit, exclusion reason and implicit/direct normalized weight; arbitrary equality hooks cannot run before refusal
- raw integers and direct integer converted/output values cannot be null; stored source/key/support Unicode labels must fit declared width; over-width valid query strings still yield row_key_not_found
- shown support reasons obey displayed missing/min_count/weighted-zero policy, unweighted counts/sums are count-derived, and a shown final-stage record agrees with enclosing final value/reasons

No constructor implements a second reducer, omitted-cell resolver, lineage proof engine or heap inspector. Coherent forgery remains the responsibility of public replay.

## Eager-memory installation clarification

For the implemented eager-memory transaction, a cooperative cancellation observed before the final checkpoint prevents rename. A later observation may accompany installed output. Atomic no-replace installation does not imply Python-bytecode-atomic receipt capture or delivery against arbitrary asynchronous caller exceptions or forced termination. Preserve caller signal policy. For a catchable caller interruption after an installation attempt, the interruption is re-raised as the same exception object with its existing notes and exception-chain details while original-inode reconciliation is attempted. Earlier source or replay validation may shorten traceback and chaining details to release temporary state; it preserves the exception object and notes, but does not promise cause/context preservation. Reconciliation remains best effort under repeated interruption. Cleanup never removes the requested destination. See MEMORY-COMMIT-INTERRUPTION.md. Supervised file-native launch/handler promises remain separately gated.
