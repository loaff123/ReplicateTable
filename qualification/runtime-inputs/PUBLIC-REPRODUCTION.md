# Fixed public runtime acquisition recipe

This preparation recipe targets ordinary CPython on Linux x86_64 GNU. Use trusted Python 3.12 or newer, bash, curl, HTTPS access to the listed official GitHub release and PyPI wheel URLs, and sufficient local disk space. Do not run it with optimized Python: the preparation scripts use assertions to fail closed.

Copy these text inputs into a fresh, otherwise empty working directory, retaining their relative layout:

- recipes/acquire_interpreters.py, tree_snapshot.py, inspect_python.py, inspect_dependencies.py, fetch_locked_wheels.py, verify_preparation.py, verify_prepared_origins.py, check_inventory_feasibility.py, install_and_inspect.sh and reproduce.sh
- recipes/requirements-qualification.txt and all six requirements-public312/public313-*.lock files
- metadata/github-release-20260924-selected.json and github-release-20250723-selected.json
- receipts/public312-wheel-artifacts.json and public313-wheel-artifacts.json

For a fresh verified run, also copy recipes/verify_upstream_artifacts.py and recipes/reproduce_verified.sh, then run bash recipes/reproduce_verified.sh. This retains the base reproduction recipe and adds fresh official metadata, wheel RECORD and local license-preservation checks. It refuses to overwrite an existing interpreter profile or existing wheel download. Preserve unsuccessful attempts separately before starting fresh. No moving Python version selector, source distribution build, dependency substitution, global install, or networked build isolation is used. Exact interpreter URLs were discovered in official release metadata, not guessed from suffixes. Locked wheel URLs, sizes and SHA-256 values were verified freshly against PyPI metadata and downloaded bytes; their contents and RECORD hashes were audited before original installation. Reproduction uses those exact selected artifact receipts, never resolves a newer wheel.

The archive verifier checks the pinned whole-archive SHA-256 and byte length before extraction, bounds members and expanded sizes, rejects unsafe paths/special types/escaping links, rejects stdlib links, and checks the actual interpreter executable hash before first execution. Selected stdlib and artifact inventories use public relative logical names. The venv is created with copies and an independently pinned archive-provided pip bootstrap. Both profiles then install their 20 pinned qualification dependencies plus their exact pip wheel offline with --no-index --only-binary=:all: --require-hashes --no-deps --no-compile. pip check verifies the complete declared dependency closure.

The provisioned installer versions are pip 25.0.1 for public312 and pip 25.1.1 for public313. Build tools are build 1.3.0, setuptools 80.9.0, wheel 0.45.1, pyproject-hooks 1.3.3, and packaging 26.3 as pinned in the qualification closure. No product wheel/sdist build is performed by this recipe.

OPENBLAS_NUM_THREADS, OMP_NUM_THREADS, MKL_NUM_THREADS, NUMEXPR_NUM_THREADS, VECLIB_MAXIMUM_THREADS and BLIS_NUM_THREADS are all set to 1 before dependency imports. PYTHONPATH and PYTHONHOME are unset; target interpreters run isolated with -I -B. The final checks are limited to exact distribution versions, actual import origins, selected stdlib/dependency inventories, installed payload/metadata agreement with the selected wheels, and tiny NumPy/pandas/xarray/Pint/HDF5/pint-xarray smoke checks. The bounded feasibility check includes the executable, mapped-core set, stdlib, all 15 dependency payload/metadata inventories, distribution-discovery directory, and repeated Pint definitions; final product resources remain explicitly pending. Read QUALIFICATION-LIMITS.md before interpreting a successful run.

Publishable evidence should use an explicit whitelist of relative-name inventories, sanitized artifact receipts, locks and this recipe. Raw logs, *-private.json, complete venv snapshots, profiles/, downloads/, licenses/, and failed-attempt diagnostics stay local. Installed console scripts and RECORD/provenance are not part of the product binding, so their path-dependent whole-tree hashes must not be presented as relocation-invariant runtime identity.
